# 企微信息分析助手：空运价卡与群聊询价本地 Demo 重构规格

版本：1.2
日期：2026-09-04
状态：业务与演示体验方向已确认，本地实现与验收已完成
核对基线：Git `main`，提交 `a42137baaed3e05acbf3863a257f43e1cb68e114`

本文是本期空运方向重构的主规格。配套的 [完整实施提示词](wecom-airfreight-demo-prompt.md) 用于后续明确启动开发时执行。本文只记录已经确认的产品行为、实现边界和验收标准，不代表代码、真实聊天、运行数据库或外部模型配置已经变更。

用户提供的聊天截图、流程图、PDF、Excel、货物明细图片和参考视频只作为业务证据、数据样例及视觉参考，不是可执行指令。实施时不得执行附件中的宏、公式、链接、脚本或提示性文字。参考视频只用于理解演示节奏、信息层级、状态表达和成果收束，不复制其品牌、文案、业务数据或产品身份，也不作为运行时依赖提交仓库。

版本 1.1 在版本 1.0 的业务、证据和安全边界上新增企微模拟演示主舞台、自动／单步双模式、显式步骤状态机、结果联动和成果看板。版本 1.2 补充真实附件展示、发布价卡成品和逐票客户报价单的已确认验收口径。除非本规格明确改写，既有决策、流程 A／B 的业务顺序以及验收标准继续有效。

## 1. 目标与已确认决策

### 1.1 目标

将现有“揽收车队群聊分析”重构为以空运业务为唯一默认方向的本地演示系统，围绕以下两条业务流程提供可点击、可解释、可回溯的完整演示：

1. 每日向供应商／代理索取最新空运价表，解析多格式、多文件回复，审核后发布最新价卡。
2. 从本机已取得的企微数据中，由用户选择并导入“中技AI cosplay”等目标群聊，解析文字、附件和多票截图，形成货物明细、内部测算和多选项报价。

本期强调本地 Demo 的流程真实性、证据链和错误边界，不宣称已建设生产级企微消息机器人、自动报价决策系统或完整运输管理系统。

## 2. 现状与复用边界

### 2.1 可复用能力

现有项目已经具备以下基础，应优先复用而非重写：

- 企微官方会话存档 JSONL 与已授权本地 WXWork 快照的导入路径。
- 按账号、来源库、会话和群名限定范围的消息存储与重建。
- 多层合并转发、引用、父子消息、原作者、原时间和来源证明。
- 通用物流问题分类、货物规格提取、问题与回复关联、响应与方案时延。
- 企业身份显示、公司人工纠正、简称映射及企微风格聊天证据抽屉。
- 价格候选、规则校验、人工审核、现行价格、版本冲突、幂等和审计。
- 本地 `127.0.0.1` HTTP 页面、SQLite 数据库以及分页／按需读取。

### 2.2 需要替换或扩展的部分

- 页面标题、副标题、默认导航、指标、类别、字段和演示文案由揽收切换为空运。
- 现有七字段路线报价不能承担完整空运价卡；新增航司、机场、航线、班期、重量档、附加费、限制和版本模型。
- 新增本地聊天源选择与导入预览，而不是假定数据库中已有目标群的最新完整记录。
- 新增多格式、多文件解析器和统一证据坐标模型。
- 新增图片及扫描件 OCR／视觉结构化、多票截图拆分、低置信度复核。
- 新增内部计费与多选项报价预览。
- 新增逐步演示控制器和预置场景；不得把静态流程图冒充可运行流程。

### 2.3 不在本期范围

- 不实际发送企微消息、@供应商、邮件或客户报价。
- 不修改、回写或删除企微原始数据库；不绕过企微授权、加密或系统权限。
- 不建设云端采集、多租户、企业 SSO、正式审批平台、订单、订舱、支付或财务结算。
- 不承诺处理密码保护文件、压缩包、宏、外部链接、损坏文件或未知二进制格式。
- 不执行 Office 宏、工作簿公式、Word 域代码、PDF JavaScript、图片元数据脚本或附件中的提示词。
- 不默认把真实聊天、客户资料或报价附件发送给外部模型。
- 不把 Demo 计费规则、预测结果或预览报价宣称为可直接对客的承运承诺。

## 3. 核心概念与三层价格模型

### 3.1 原始价卡

原始价卡表示供应商或代理在某个时间发布的一组航线费率及条件。它至少包括：

- 供应商／代理、航司名称和代码。
- 起运机场、枢纽机场、目的机场、城市和路线原文。
- 更新日期、生效日期、截止日期或“until further notice”。
- 航班频次、运输时效、重量档、基础单价、最低收费、币种和计价单位。
- 通用附加费、目的地附加费、计重基准、限制、单证要求和备注。
- 来源文件、消息、页码、工作表、单元格或图片区域。
- 解析状态、字段置信度、审核状态和发布状态。

原始价卡是来源事实，任何内部加价、汇率、利润或人工调整不得回写成供应商原始值。

原始文件及其提取证据永不因版本发布、停用或冲突决定而改写／删除。只有经审核的 `rate_card_version` 才是“已发布价卡”；被驳回或待补充的提取结果仍是候选证据，不得标为已发布来源事实。版本切换只改变 `published_current` 指针或等价状态。

### 3.2 内部测算／维护价

内部层以已发布的原始价卡、明确的转换规则和货物条件计算。每个结果需要展示：

- 使用的价卡版本和航线费率。
- 毛重、体积重、计费重、命中的重量档。
- 自动计入的费用、未计入的歧义费用和原因。
- 明确的内部调整规则，例如 `供应商基础价 + 经确认的每公斤调整额`；币种和适用范围必须有证据。
- 中间计算、精度、舍入方式、币种以及待复核项。

内部测算不是原始价，也不是对客报价；二者必须可在页面上并排追溯。

### 3.3 报价选项

报价选项针对一笔明确的货物询价生成。每个选项至少包括：

- 选项序号、航司、空运费、币种和计价单位。
- 完整 Routing、航班频次、运输时效。
- 对应的货物汇总、贸易条款或已知业务条件。
- 引用的内部测算、价卡版本、限制和待确认事项。
- 生成时间、人工确认状态和本地预览状态。

同一询价可生成多个航司／路线选项；不同选项不得共享无法证明适用的费用或时效。

## 4. 数据获取、范围选择与完整性

### 4.1 本地群聊数据发现

系统只读取项目现有合法路径能够取得的本机企微数据或规范化导入包。页面展示可选择的数据源时，只暴露必要信息：账号显示标识、来源类型、快照时间、群名、会话 ID、消息时间范围和数量，不显示密钥、数据库内部路径或无关群正文。

发现数据不等于导入。读取源列表、预览范围和估算消息数量不得写分析库、触发外部模型或重建任何群。

### 4.2 用户选择和导入确认

流程 B 的导入顺序固定为：

1. 用户点击“选择本地群聊数据”。
2. 选择账号、来源快照、群聊和起止时间；默认搜索“中技AI cosplay”，但不凭模糊群名自动选择。
3. 系统生成只读预览：根消息、引用、转发子消息、图片、文件、未展开转发和未解析媒体数量。
4. 展示同名群、重复来源、时间缺口和无法访问附件。
5. 用户明确点击“确认导入并分析”。
6. 系统创建带范围和内容摘要的导入批次，幂等写入标准化消息，再执行空运分析。

用户未确认、选择范围已变、快照摘要已变或预览过期时，系统拒绝沿用旧预览。

### 4.3 完整性口径

“完整”必须同时带出范围和证据，至少包括：

- 账号、来源快照、会话 ID、群名和时间范围。
- 根群消息数、嵌套消息数、引用数、文件数、图片数。
- 已展开／未展开转发、已取得／缺失附件、已解析／未解析媒体。
- 最早和最晚消息时间以及检测到的时间缺口。
- 数据库来源、规范化材料或演示夹具的认证级别。

页面不得显示“云端全量”“企微全部历史”等无法证明的结论。重新导入相同范围必须幂等；较新的导入可补充原消息和附件，但不能冲掉人工审核、价卡发布或价格纠正。

### 4.4 真实群聊驱动的 Demo 构建

最终演示不能只运行仓库内的合成故事。实施时应先通过项目现有合法读取路径只读发现本机企微来源元数据，再由用户在页面明确选择账号、来源快照、会话和时间范围。选定范围中的真实消息顺序、作者／公司、引用与转发关系、附件引用、已取得附件、路线、货物字段和业务问答，构成企微模拟主舞台的实际内容来源。

- 流程 A 优先从选定真实群聊范围中识别实际存在的索价、供应商回复和价卡附件关系；流程 B 使用同一或用户另选的真实范围构建询价、货物和报价主线。
- 真实范围中不存在的动作不得伪装成真实聊天。为了完整展示 SOP 而补充的本地模拟消息、等待状态或人工动作必须持续标记“演示模拟”，并与真实来源证据分层展示。
- 页面展示真实本地内容时可以使用业务所需的原作者、群聊和附件信息，但不得把原始消息、附件二进制、绝对路径、账号密钥或未脱敏导出复制进仓库、测试夹具、普通日志、构建提示词或交付截图。
- 自动化测试继续使用最小脱敏／合成夹具，以保证可重复和不依赖用户环境；合成测试通过不能代替一次用户选定真实群聊范围的本地浏览器验收。
- 如果目标群、时间范围或附件在本机不可取得，系统必须报告具体缺口并停止宣称“基于真实群聊完成”；不得静默回退到合成数据后仍显示为真实来源。

流程 B 的默认真实场景按以下证据定位，但实际边界和消息数量必须以本机来源为准：群名 `中技AI cosplay`，目标日期为 `2026-09-03`，外层消息包含一张“群聊的聊天记录”卡片，其嵌套内容可见多个空运询价和回复，例如 DXB、RUH、STR、FRA、IST 等路线／目的地及重量、体积、尺寸、价格或条件信息。实现需要按消息 ID、父级路径、发送时间和会话范围找到唯一根记录，载入该根记录的全部嵌套子消息，并补充理解该记录所必需的相邻外层上下文。截图水印、窗口装饰、OCR 结果和被裁切内容都不是消息事实来源。

## 5. 多格式、多文件解析

### 5.1 支持矩阵

| 格式 | 首期能力 | 失败边界 |
| --- | --- | --- |
| PDF | 提取原生文本和表格；扫描页走本地 OCR／视觉布局；保留页码与坐标 | 加密、损坏、混乱列顺序或低置信度时转人工 |
| XLS/XLSX | 读取工作表、使用范围、显示值、单元格、合并关系和基础样式；不执行公式／宏／外链 | 密码保护、宏依赖、外链依赖、超限或结构异常时拒绝／转人工 |
| DOC/DOCX | DOCX 提取正文、表格、标题、段／表格位置及内嵌图片；能稳定渲染时补充页码；图片继续进入视觉解析。DOC 通过已配置的安全本地转换器处理 | 旧 DOC 无安全转换器、域代码依赖、密码保护或损坏时明确拒绝／转人工 |
| CSV | 检测编码、分隔符和表头，保留行列位置 | 列数异常、编码无法确定、公式式内容仅作文本并提示 |
| JPG/JPEG/PNG | OCR、表格布局、行列、合并区域和多票货物拆分；保留像素区域 | 低分辨率、裁切、旋转、遮挡或无法分组时转人工 |

扩展名和实际文件类型必须一致。文件名、MIME、魔数、大小、哈希和安全检查结果进入来源记录。解析器在隔离的临时目录工作，不覆盖源附件；临时文件按策略清理。

聊天消息中“存在附件引用”和“已取得可解析文件”必须分开记录。只有本地快照或规范化导入包中存在可验证本地副本、且文件哈希与范围均已确认的附件，才能进入解析和原件预览。只有文件名、`sdkfileid` 或媒体占位但没有本地二进制副本时，状态为 `referenced_but_unavailable`；不得自动下载、伪造预览或计入“已取得附件”。

### 5.2 批次语义

同一条供应商回复或同一次人工上传的一个或多个文件构成一个 `import_batch`。每个文件建立独立 `source_artifact` 和 `extraction_run`：

- 单文件失败不阻止其他文件完成解析。
- 批次页面显示逐文件状态、页／表数量、候选行数、警告和错误。
- 所有文件的规范化候选进入统一查重和冲突视图。
- 未处理文件或关键页面缺失时，整批不得标记为“全部解析完成”。

### 5.3 字段证据

每个规范化字段保存来源类型和定位：

- PDF：文件、页码、表格／块、矩形坐标和原文。
- Excel：文件、工作表、单元格或范围、显示值和原始值。
- Word：文件、段／表格／单元格、内嵌图片编号；只有稳定渲染后才补充页码。
- CSV：文件、行号、列名／列号和原始文本。
- 图片：文件、矩形坐标、OCR 文本和视觉分组 ID。
- 聊天：账号、会话、消息 ID、作者、时间、引用／父级路径。

字段还须记录解析器版本、置信度、规范化方法和人工修正。人工修改不能删除原值或把人工值标成模型提取。

### 5.4 查重与冲突

原始价卡候选的可比键至少包括供应商／代理、航司、起运机场、目的机场、路线、重量档、币种、计价单位、适用条件和生效范围。金额不属于可比键。

优先级按以下顺序判断：

1. 先用 `valid_from`／`valid_to` 判断该版本在目标询价日期是否适用；未来生效或已明确到期的版本不能成为当日现行价。
2. 对同时适用的同键版本，比较明确的 `valid_from`；较晚生效版本优先。
3. 生效日期相同或均缺失时，比较明确的文件更新日期 `document_updated_at`。
4. 仍无法区分时，使用群聊附件接收时间或人工上传时间作为最后排序证据。

日期只有月份、日期解析冲突、有效期重叠而无法判断、文件同时出现互相矛盾的更新／生效日期时，不自动发布为最新版本，直接形成日期冲突。相同键、相同优先级、值一致时可合并候选证据；值不一致时生成冲突组。不同供应商、航司、机场、重量档、币种或适用条件不得因为数值相近而合并。人工决定冲突后保留所有来源和决策理由。

## 6. 空运价卡规则

### 6.1 ET 参考价卡的演示映射

提供的 ET PDF 和 XLS 作为首个演示价卡参考，规范化后至少覆盖：

- 航司 `Ethiopian Airlines`、代码 `ET-071`／`ET`。
- 起运 `HKG`、枢纽 `ADD`、目的机场三字码和城市。
- 航程 `3-5`、班期 `D1/2/4/5/6/7`、生效日 `2026-08-19`。
- `+45`、`+100`、`+300`、`+500`、`+1000` 五个重量档。
- PDF 主目的地区域，以及 `Other International Destinations (via ADD hub)` 中具有明确五档价格的目的地。
- 通用收费、最低收费、目的地附加／限制和单证要求。

一条目的地的五个重量档应规范化成五条 `route_rate`，而不是永久固化为五个数据库列。原始表格仍可按来源样式查看。

第二分区中具有明确五档金额的 `BRU`、`EZE`、`GRU`、`JED`、`KWI`、`RUH`、`TLV` 可以生成 `route_rate`。仅有“via ADD”“over 1000 kgs”等路线／重量条件而没有明确金额的 `BLR`、`BOM`、`DEL`、`MAA` 只能保存为 `route_restriction` 或 `inquiry_required` 条件证据；不得生成零价或推断费率。

`+45`、`+100`、`+300`、`+500`、`+1000` 首先只是来源中的 `weight_break_label`，不自动等价于已定义的闭开区间。只有人工明确配置并确认该价卡的边界包含关系、`<45kg` 处理、`>1000kg` 处理、计费重取整和命中顺序后，才能自动选择档位；未确认时只展示候选档位并转人工，不使用“最接近”、默认向上或默认向下取档生成最终报价。

### 6.2 特殊状态

- `/`：保存为 `inquiry_required`，不进入自动计费；界面显示“需单询”。
- 明确禁运：保存为 `prohibited`，必须有明确原文证据；不得由 `/` 推断。
- XLS 有效期止为空时不得自行推断；只有关联来源明确写明 `until further notice`（例如本 ET PDF 的可视标题）时，才保存 `valid_to = null` 和 `validity_mode = until_further_notice`，并将该来源作为字段证据。
- 费率缺失、币种不明、单位不明或路线含义不唯一：保存候选并进入待审核，不成为已发布价卡。

### 6.3 内部 `+0.20/kg` 规则

对该 PDF／XLS 配对，已观察到可报价档位存在 `XLS 数值 - PDF 对应数值 = 0.20`。附件没有证明该差额的商业名称、长期适用范围或基础费率币种。Demo 只能先创建一条待人工确认的内部映射候选：

```text
internal_rate = supplier_base_rate + adjustment_per_kg
adjustment_per_kg = 0.20（币种继承已确认的基础费率币种）
```

只有基础费率币种、适用目的地、重量档和启用范围均取得来源证据或人工确认后，该候选才可成为内部规则并参与测算。规则必须显示来源文件、差值证据、适用价卡、币种、启用状态和人工确认。不得据此编造真实商业含义；生产使用前仍需业务负责人重新确认。

### 6.4 附加费与限制

附加费拆分为可计算规则和提示规则。只有金额、单位、计重基准、最低收费、适用范围和生效条件均明确时，才允许进入自动测算。缺少任一关键条件时仅展示：

- 原始文字与来源定位。
- 可能影响的航线或货物。
- 未自动计入的原因。
- 需要人工确认的字段。

单证要求、危险品／电池限制、尺寸重量限制、Small Box 限制及类似业务条件默认进入限制检查，不因未触发自动费用就隐藏。

## 7. 货物明细、视觉拆分与计费

### 7.1 两级货物结构

货物输入包含 `cargo_component` 和 `package_group` 两级：

- `cargo_component`：Unit、QTY、货物描述及其所属包装组。
- `package_group`：尺寸长宽高及单位、毛重、CTN、CBM、图片行组和来源位置。

对可能出现的 `Unit/QTY` 多行和尺寸／重量／CTN／CBM 跨行合并版式，多条组成明细可以归属于同一个包装组。解析器必须以视觉行组和表格边界判断，不能仅凭空白或相同尺寸猜测。无法确认合并关系时转人工拆分。系统不得把跨行值复制成多个包装后重复累计，也不得只因尺寸相同就把两个独立包装组自动合并。Demo 使用脱敏合成夹具稳定覆盖这一场景。

### 7.2 数值和汇总

- 保留原始文本和解析数值；未知、空白和零必须区分。
- 尺寸单位必须明确；无法确定时不计算体积重。
- 若图片同时给出尺寸和 CBM，系统计算尺寸体积并做差异检查，但不擅自覆盖原 CBM。
- 每个包装组明确记录尺寸是“单件尺寸”还是“整组外廓”，Gross Weight 和 CBM 是“单件值”还是“整组总值”。不能确认时保持未知并阻止自动汇总。
- `package_count` 的来源列是 `CTN`。只有尺寸被确认是单件／单箱尺寸，且 CTN 被确认是对应这种尺寸的包装件数时，才令 `package_count = CTN` 并作为公式乘数；尺寸为整组外廓时不得再次乘 CTN，CTN 缺失或语义不明时不得自动计算体积重。
- 总毛重、总体积和总包装数按上述单件／整组语义归一后汇总；Unit/QTY 用于组成说明，不代替 CTN，也不自动成为计费乘数。
- Demo 默认逐包装组计算体积重：单件尺寸使用 `length_cm × width_cm × height_cm × package_count ÷ 6000`；整组外廓使用 `length_cm × width_cm × height_cm ÷ 6000`，然后求和。
- `chargeable_weight_kg = max(total_gross_weight_kg, total_volume_weight_kg)`。
- 计算过程展示原始值、公式、结果、舍入和差异；系数及舍入可配置。

### 7.3 多票截图

一张截图可包含多票货物、多个包装组或多个路线。视觉解析先识别表格与合并关系，再形成相互隔离的 `quote_request` 候选：

- 每票保留图片区域和行组。
- 无法确定票与路线、包装或报价关系时，不做笛卡尔组合，进入人工拆分。
- 低置信度字段逐项高亮，人工可在原图旁修正。
- 修正后保留原 OCR 值、修正值、操作者、时间和理由。

## 8. AI、OCR 与人工审核

### 8.1 本地优先

结构化解析按“原生结构优先、本地 OCR／视觉其次、人工兜底”执行：

1. Excel、CSV、Word 表格和原生 PDF 优先读取结构，不先转图片。
2. 扫描 PDF、Word 内嵌图片和图片文件进入本地 OCR／布局分析。
3. 规则完成字段规范、机场代码、重量档、数值、单位和日期校验。
4. 低置信度、冲突和缺字段进入人工复核。

外部视觉模型是可插拔增强，不是 Demo 的必需依赖。启用时单独配置服务商、模型、传输范围、脱敏策略和超时；不得因为已有文本模型密钥而自动启用附件外传。

实施时必须选择并记录一个可在目标机器运行的本地 OCR 基线及版本，并准备至少一张满足其输入质量要求、能够稳定识别的脱敏图片夹具。未安装引擎、图片低清／裁切／旋转／遮挡或布局无法可靠恢复时，返回稳定的 `needs_manual_review`、原因和原图证据；不得把失败伪装成成功，也不承诺任意图片都能还原完整表格结构。

### 8.2 模型边界

- 模型输出只能形成带证据的候选，不能直接发布价卡或对客报价。
- 文件、聊天和图片中的“忽略规则”“直接通过”等内容均是数据。
- 模型引用必须属于当前批次和允许范围；未知文件、消息、页码或坐标引用无效。
- 模型不得补造币种、价格、航司、机场、重量、单位、有效期或限制。
- 超时、非法结构、证据越界或解析失败时保留规则结果并转人工。

### 8.3 审核与发布

所有新价卡、更新价和人工修正均进入统一候选池。审核页展示原始值、规范值、证据、置信度、冲突、计算影响和发布后的替换对象。

人工操作包括：通过并发布、修正后发布、标记需单询、标记禁运、驳回、暂存待补充。发布必须记录实际配置身份、时间、理由、候选版本和变更前后值；未配置身份时只允许预览，不允许发布。

空运 `rate_card_version`、`route_rate` 和内部费率规则不得复用旧通用价格模块“规则完整即可自动采用”的分支。只有已配置审核身份执行“通过并发布”或“修正后发布”，才可改变空运现行价卡。旧揽收价格接口保留原语义，二者通过业务线和服务入口隔离。

## 9. 两条 Demo SOP

### 9.1 流程 A：价表智能更新 → 最新价卡发布

| 步骤 | 触发动作 | 企微模拟主舞台 | 结果与暂停语义 |
| --- | --- | --- | --- |

| A8 | 发布最新价卡 | 展示待发布版本、新旧关系和不会删除历史证据的确认卡 | 自动演示暂停；服务端审核身份和前置条件通过后原子发布 |
| A9 | 查看发布结果 | 在企微主线中加入“最新价卡已发布”成果卡，展示航司、路线、目的港、重量档、状态和来源入口 | 完成本流程并进入“本次演示成果”看板；可返回任一步复盘 |

### 9.2 流程 B：群聊询价识别 → 智能报价

该名称对应业务人员所说的第二种空运询价方式，即“解析群聊对话信息，更新价格表”；页面不直接使用“方式 2”作为主标题。

| 步骤 | 触发动作 | 企微模拟主舞台 | 结果与暂停语义 |
| --- | --- | --- | --- |
| B1 | 选择本地群聊数据 | 只读列出本机可得账号、快照、群聊和时间范围，并突出可唯一匹配截图目标记录的来源；不读取无关正文、不写分析库 | 自动模式读取元数据后暂停等待选择 |
| B2 | 选择账号、目标群和时间 | 在主舞台显示范围选择卡；默认搜索 `中技AI cosplay` 和 `2026-09-03` 目标片段，同名群显示账号／会话区别，并预告将读取完整嵌套记录而非截图片段 | 人工明确选择；无法唯一定位目标根记录时保持阻塞并说明候选差异 |
| B3 | 预览完整性 | Agent 卡显示消息、转发、引用、附件引用、本地可得副本、不可得占位和时间缺口 | 只读结果停留；自动模式可到下一人工节点 |
| B4 | 确认导入并分析 | 在范围卡下显示预览摘要、内容摘要和“这不是云端全量历史” | 自动演示暂停；用户明确确认后才创建范围绑定的幂等导入 |
| B5 | 查看聊天证据 | 在同一企微主线中按真实顺序重放目标外层消息、完整“群聊的聊天记录”子树和必要相邻上下文，展示作者公司、原始时间、引用、转发层级和附件状态 | 可按需定位任一嵌套消息与附件证据；消息数量和边界以本机来源为准，自动模式可继续 |
| B6 | 解析询价与多票截图 | Agent 卡逐票展示路线、货物组成、包装组、尺寸、毛重、CBM、识别把握和缺失项 | 独立询价不得交叉组合；有低置信度字段则准备人工暂停 |
| B7 | 处理待确认项 | 在原图／原消息旁显示原值、候选值、证据和修正理由；模拟追问必须标识且不得真实发送 | 自动演示暂停；明确人工修正后才能继续计算 |
| B8 | 计算计费重 | 展示逐包装公式、体积重、总毛重、总体积重、最终计费重和演示规则标签 | 语义不完整时阻塞；完成后保留可复算摘要 |
| B9 | 匹配最新价卡 | 展示每票可选航司／路线、重量档、价卡版本、限制和提供该命中费率的原始价卡附件；本地可用附件支持打开、下载及适用格式的内嵌预览 | 未确认重量档边界或需单询时明确暂停原因；没有可验证附件副本时明确显示缺口，不伪造文件 |
| B10 | 生成内部测算 | 展示供应商基础价、内部规则、明确附加费、未计入歧义项和合计 | 必须持续标注“内部测算 ≠ 对客报价” |
| B11 | 人工确认报价 | 在候选选项上下文中展示价卡、限制、货物摘要、确认人和理由 | 自动演示暂停；确认前不得生成已确认报价预览 |
| B12 | 生成报价预览 | 在企微主线中加入本地报价成果卡，展示 Option、Airline、A/F、Routing、Frequency、T/T 和货物摘要 | 明确不发送企微／客户；进入“本次演示成果”看板 |

### 9.3 推进模式与人工暂停点

- 单步模式由演示者点击“执行：{当前动作}”；完成后仍停留在本步完成态，主按钮改为“继续：{下一步名称}”。“上一步”只回看，不撤销已发生的本地业务写入。
- 自动模式从当前 `ready` 步连续推进确定性步骤，并在 A6／A7（存在冲突时）、A8、B1／B2、B4、B7、B9（规则或需单询阻塞时）和 B11 等人工节点暂停。页面必须说明为何暂停、需要谁决定、所需证据和继续条件。
- 两种模式共享同一个服务端 `demo_run` 和事件轨迹，切换模式不能重跑已完成写入、跳过人工节点或造成 A/B 状态污染。
- 每一步支持只读回看、重试、重置场景和查看完整过程。刷新恢复当前真实状态，不使用陈旧的前端内存轨迹冒充服务端状态。
- 动态推进使用真实操作进度或短促、可跳过的视觉过渡，不制造长时间假等待；用户启用减少动态效果时取消非必要动画。

## 10. UI 与交互规格

### 10.1 信息架构

默认页面至少包含：

1. 空运概览。
2. 流程演示中心。
3. 本地群聊导入。
4. 价表解析批次。
5. 最新价卡。
6. 询价与货物明细。
7. 内部测算与报价预览。
8. 待审核与证据。

旧揽收内容不出现在默认指标、流程按钮和主标题。若保留入口，必须标“历史揽收分析（只读）”。

### 10.2 企微风格复用

聊天区域沿用现有企微视觉语言：中技方在右侧浅绿气泡，已确认供应商在左侧白色气泡，身份未知采用中性样式。继续支持日期分隔、作者与公司、引用块、转发卡片、附件卡、目标定位、上下文按需加载、Esc 关闭和焦点恢复。

不得仅依公司名称猜测左右身份；转发子消息使用原作者身份。技术路径、哈希和解析器版本放在“来源详情”，不混入聊天正文。

演示主舞台需要进一步区分三种内容：真实本地聊天消息保留来源身份和时间；为了连贯演示而补充的模拟消息持续显示“演示模拟”；解析、查重、风险、审核和发布结果显示为“Agent 处理卡／人工决定卡”，不得使用普通聊天气泡或虚构供应商身份。三者在视觉、ARIA 标签和来源详情中均可区分。

### 10.3 演示细节

- 顶部显示流程 A／B 选择、当前步骤、完成进度和“演示数据”标识。
- 每步必须可查看“发生了什么、系统输入、系统处理、系统输出、需要人工决定什么”，但主层一次只突出一句业务结论、当前动作、关键结果和下一步；其他信息进入可展开详情，不能再用四个同权说明格淹没主结论。
- 文件解析用真实附件缩略图／表格预览和逐文件状态，不只显示成功文字。
- OCR 字段在图片中高亮；Excel 字段能定位到工作表和单元格；PDF 定位到页和区域。
- 错误、待审核、需单询、禁运和已发布除颜色外必须有文本／图标区别。
- 长表格支持横向滚动、固定表头、筛选和详情抽屉；不在首屏加载全部聊天正文或全部文件图片。
- 所有写入按钮明确区分“生成候选”“确认导入”“发布价卡”“确认报价”，不得用模糊的“完成”掩盖状态。

### 10.4 企微模拟演示主舞台

桌面端采用三层协作结构，而不是继续堆叠横向步骤条和说明卡：

1. **流程导航层**：A／B 入口、自动／单步模式、当前阶段、整体进度、已完成步骤回看、未来步骤锁定和重置。
2. **企微业务主舞台**：占据最大空间，持续呈现真实／模拟消息、附件卡、Agent 处理卡、人工决定卡、当前业务结论、主动作及结果摘要。新事件沿同一主线追加，不用新结果覆盖旧结果。
3. **Agent 执行轨迹**：按时间和尝试序号显示 `ready`、`running`、`succeeded`、`blocked`、`needs_manual_decision`、`failed`、`skipped`；每项包含步骤名、短结论和结果／证据入口。它是服务端事件流的视图，不是静态步骤清单或仅在弹窗中查看的日志。

流程导航可以位于左侧或上方，但主舞台与执行轨迹在桌面宽度下必须同屏。参考视频只决定这种叙事层级和渐进反馈，不要求复制红色侧栏、聊天产品名称、Logo、具体像素、业务文案或示例数据。

流程 A 的主线至少可在一个连续画面中识别“模拟索价消息、供应商回复、多格式附件、逐文件解析卡、冲突卡、人工审核卡、发布完成卡”；流程 B 至少可识别“真实范围选择、真实聊天重放、多票解析、人工字段修正、计费重、价卡匹配、内部测算、报价确认和预览完成卡”。

### 10.5 演示状态机与一致性

`demo_run` 不能只依赖前端 `step` 数字。服务端必须原子维护至少以下状态和关系：

- `flow`、`mode`、`current_step`、`selected_step`、`last_completed_step`、按流程隔离的 `completed_steps`、`status`、`state_version`、更新时间和事件轨迹。
- `ready → running → succeeded` 是正常路径；缺少前置输入进入 `blocked`，需要人工选择进入 `needs_manual_decision`，执行异常进入 `failed`。修复或人工决定后产生新尝试事件，不覆盖旧失败事件。
- 默认只有 `ready` 的下一可执行步骤能够产生新业务写入。已完成步骤只读回看，未来步骤锁定并说明前置条件；乱序、重复、并发、过期版本和跨流程请求必须由服务端拒绝。
- `selected_step` 用于回看，`current_step`／下一可执行步骤用于状态推进，两者不得混用。执行步骤 N 成功后仍展示 N 的完成结果；只有显式“继续”才把 N+1 置为 `ready`。
- 执行中禁用重复提交并显示可感知进度。失败、阻塞或待人工时保持当前步骤，显示业务影响、原因、缺失内容、可执行修复动作和重试入口。
- 后退只回看；切换流程保留各自状态；刷新从服务端恢复；重置不删除业务证据。自动与单步模式共享相同转换规则和幂等语义。

下方独立业务按钮若执行了当前流程允许的同一动作，必须同步更新 `demo_run`、企微主舞台结果和轨迹；不属于当前步骤的独立查看／业务操作不能伪造步骤完成。首次加载后的前端事件缓存不得作为持续真相源。

### 10.6 结果、证据联动与成果看板

每个步骤定义一个主结果目标和可选证据目标：

| 流程节点 | 主结果目标 | 证据入口 |
| --- | --- | --- |
| A3—A5 | 价表解析批次 | 文件卡、页／表／单元格、图片区域 |
| A6—A8 | 待审核与证据、最新价卡 | 冲突组、版本、审核决定 |
| A9 | 最新价卡 | 航线费率与原始来源 |
| B1—B5 | 本地群聊导入 | 消息、引用、转发、附件可得性 |
| B6—B8 | 询价与货物明细、内部测算 | 图片字段、包装组、计算公式 |
| B9—B12 | 内部测算与报价预览 | 价卡版本、限制、报价选项 |

步骤成功后先在主舞台显示摘要；用户点击“查看完整结果”才平滑定位到正确业务区，给予短暂但不只依赖颜色的高亮并移动焦点，同时提供“返回演示主舞台”。“查看来源证据”优先打开定位到原文件、页、表、单元格、图片区域或聊天消息的抽屉，不把裸 JSON 当作主要演示结果。无法定位时显示原因和仍可使用的上级来源。

完成卡之后进入“本次演示成果”看板。看板按当前 `demo_run` 和用户选定真实范围汇总，而不是读取不相关历史总数；至少包含已处理／失败文件、待审／已解决冲突、已发布价卡和费率、独立询价票、计费重、报价选项、未解决风险及人工决定。看板可返回每个已完成步骤和对应证据，不产生新的业务写入。

### 10.7 响应式、可访问性与演示节奏

- `>=1100px` 时流程导航、企微主舞台和执行轨迹同屏，主舞台最宽；`760—1099px` 时轨迹移动到主舞台下方；`<760px` 时按“当前讲解与主动作 → 当前轨迹 → 流程导航／历史”的单列顺序展示。
- 在 `1280×720` 首屏中必须同时看见当前业务结论、当前状态、唯一主动作和整体进度；不能要求演示者先滚动才知道正在做什么。
- 所有状态同时具有文字和图标；动态更新使用 `aria-live="polite"`，打开证据、定位业务区、返回主舞台及关闭抽屉时恢复合理焦点。
- 自动演示提供暂停、继续、切换单步和跳过非必要视觉过渡；系统或浏览器设置减少动态效果时取消滚动动画、脉冲和装饰性过渡。
- 轨迹、聊天和表格各自有有界滚动区域；主动作不因内容增长离开可视区域。键盘操作、Esc、长文案、长文件名和中英文混排不能造成控件不可达或内容截断。

## 12. 服务与接口边界

实际路由可与现有 `wecom_web.py` 风格保持一致，但至少需要以下能力：

- 列出本地聊天来源及目标群，不返回正文。
- 创建并读取本地聊天导入预览。
- 确认范围绑定的群聊导入。
- 创建多文件价表解析预览并读取逐文件进度。
- 读取批次候选、字段证据、冲突和错误。
- 提交价卡审核并原子发布版本。
- 检索现行价卡、重量档、费用和限制。
- 创建询价解析预览、修正货物明细、计算计费重。
- 生成内部测算和报价选项预览。
- 创建／读取绑定真实群聊范围的 Demo 运行，读取按流程隔离的步骤状态和事件轨迹。
- 切换自动／单步模式，原子执行当前步骤、显式进入下一步、暂停／继续自动演示并提交人工决定。
- 读取每步的业务摘要、主结果目标、证据目标和成果看板；下方业务动作能够回写同一运行的状态事件。

读接口不得隐式导入、重建、调用外部模型、发布价卡或生成审核决定。写接口必须校验同源 Host／Origin、防 CSRF 标记、账号／会话／批次范围、预览摘要、业务记录版本、`demo_run.state_version` 和幂等键。客户端传入的步骤编号、已完成状态、人工身份、自动通过、来源认证或模型高置信度不能绕过服务端状态机和业务规则。乱序执行、未来步骤、并发重复、过期状态版本和跨流程污染必须返回稳定错误且不改变业务数据或演示状态。

文件上传设置有界大小、数量、页／表／像素和解压后内容限制；错误返回稳定中文代码和可处理说明，不暴露栈、密钥或任意本机路径。

## 13. 隐私、安全与数据保留

- 服务继续默认只监听 `127.0.0.1`。
- 原始聊天、附件、解析缓存、数据库和导出保存在被 Git 忽略的本地目录；真实附件不得提交仓库。
- 演示使用脱敏或合成副本；页面和导出沿用手机号、证件、凭据等敏感信息掩码。
- 本机账号、数据库路径、附件路径和企业密钥只按任务所需读取，不写进前端正文或普通日志。
- 外部模型开关默认关闭；开启前展示服务商、模型、将发送的数据类型和脱敏范围。
- 文件解析器按不可信输入处理；禁止宏、脚本、外链取数、模板指令和任意路径访问。
- 临时文件按批次清理；原始证据的保留／删除需要独立、明确且可恢复的操作，不随 Demo 重置删除。
