## 1. 目标、已确认决策与非目标

### 1.1 用户目标

1. 补充企微对话各方所属公司，覆盖提问人、回复人、转发记录中的原始作者。
2. 在“路线报价与时效”板块维护起点、终点、重量、体积、包装数量、时效、价格，并提供对应 Excel 表格。
3. 将原消息及父级证据改为接近企微聊天记录的阅读体验，降低业务轮次和全量消息证据链的理解成本。

## 3. 公司信息

### 3.1 展示与来源

- 所有发送者统一展示“姓名 @公司”；未知公司显示“公司未知”，有冲突显示“公司待确认”。公司名称和“中技方／其他企业／未知主体”是不同信息，不再直接把 zhongji、other 当作公司展示。
- 业务轮次摘要显示提问方公司；报价行显示报价方公司；回复和全量消息显示各自作者公司。报价方不能误用提问方或转发者的公司。
- 子消息使用自己的作者和企业元数据，不继承父转发卡片作者的公司。仅有转发者身份时保持原作者公司未知。
- 身份依据优先使用可验证企业标识及企业名称；其次使用明确的显示名企业后缀。正文提及公司、地址中的公司名、LLM 猜测均不得直接写为主体归属。明确身份信息相互矛盾时转人工，不静默选择一方。
- 公司简介、工商背景、注册地址等资料不在本期“所属公司”的范围内。

### 3.2 人工纠正及简称映射

人工操作写入独立纠正／映射记录，保存原值、规范公司标识及名称、依据、操作人、时间、适用账号与身份范围。不得覆盖原消息、原企业元数据或来源认证标记。

简称归一须经确认；不能仅因名称前缀相同就合并不同法人，也不能跨账号按同名人员推断身份。无稳定作者标识时，纠正只作用于明确选定的记录范围。历史公司变化不得被当前公司配置一并改写。

预览受影响记录后再提交纠正；如果新映射将导致两个现行价格键合并，生成待复核冲突，不静默合并价格。保留旧 subject_bucket 的原有统计语义，本期增加公司解析／展示层，不悄悄重写全部主体统计。

## 4. 价格记录与最新状态

### 4.1 每行的含义与字段

一条可维护价格表示：某业务来源范围内，某报价公司针对明确路线、货物条件及服务时效的一种价格方案。它不是单条消息，也不是任意一条路线的通用运价。

网页与 Excel 都保留七个核心列，并可在其后增加责任及证据列：

| 字段 | 数据要求 |
| --- | --- |
| 起点、终点 | 原始地点文字、规范地点、精度／地点类别、证据引用；城市与具体机场／仓库不可无条件合并。 |
| 重量 | 数值、单位、原文；只在单位明确时做确定性换算，不凭体积反推实重或计费重。 |
| 体积 | 数值、单位、原文；未知与零不同。 |
| 包装数量 | 数量与包装类型一起保存，例如箱、托、件；1PLT 不等于 1CTN。 |
| 时效 | 原文与经确认的服务方案标识；“当天达”与“隔日达”分别维护。未经确认的同义词不自动归一。 |
| 价格 | 精确十进制金额或原始价格表达；币种、计价方式／单位必须独立保存，不能把总价和每公斤单价混合。 |
| 报价方／询价方 | 分别保存公司与人员；报价方属于匹配条件，询价方和来源语境保留用于判断是否可比。 |
| 状态与责任 | 审核状态、采用状态、判断方式、责任岗位、实际人工确认人（若有）、确认时间及理由。 |
| 时间与证据 | 报价消息时间、接收时间、维护时间分别保存；稳定记录 ID、版本、原始消息／轮次关联及字段来源。 |

每个提取字段至少可追溯到消息标识及原文片段；人工填值标明 manual 来源，Excel 值标明文件批次和行号，不能伪装成聊天原文。

当前提问、后续规格补充、报价回复可以组成一条价格候选，但必须存在明确且唯一的关联；每个字段保留自己的来源。不得把后续补充回填成“原提问已提供”。多组货物不能盲目相加，路线、规格与报价方案不能做笛卡尔积；不能唯一配对时整体转人工拆分。

### 4.2 匹配键与隔离

自动匹配至少考虑：业务来源范围、报价公司规范标识、起点、终点、重量及单位、体积及单位、包装数量及类型、服务时效、币种、计价方式／单位。金额不属于匹配键。

- 保留账号和业务会话隔离。主群页面可以汇总子来源价格，但不因此让无关子会话之间互相覆盖；来源身份无法确定时不自动跨来源合并。跨群统一价库另行设计，不在本期默认启用。
- 明示的渠道、货物限制、税费／附加费条件、客户专属条件等若影响可比性，应作为条件签名的一部分或阻止自动匹配，不能因七列相同就忽略差异。本期不建设复杂费率引擎。
- 同一公司同路线、1000kg 与 2000kg 分行；不同公司分行；同条件下当天达与隔日达分行。
- 未知字段不是通配符，多个未知也不意味着同一条件。关键条件缺失时先保存候选并待复核，不能创建可自动覆盖任意记录的“空值键”。人工可以确认某字段不适用，但必须明确记录范围与理由，不得将未知默认为不适用。
- 明确单位的等价换算可用于匹配，展示仍可查看原文。不得模糊合并城市与机场、实重与计费重、箱与托、人民币与美元、总价与单价。

### 4.3 新旧顺序与人工修正

“最新”以可信报价消息的业务时间为主要顺序，不以导入时间、审核处理时间或页面刷新时间替代。显示时间和持久化时间需区分时区。

相同条件下较新的候选通过审核后，事务性替换现行记录；较旧候选仍可留存证据，但不能因为晚导入、晚审核而覆盖较新价格。同一时间且无可信先后依据、内容冲突时转人工；稳定排序只能确定阅读顺序，不能伪造业务优先级。

人工纠正已有记录时，必须携带该记录当前版本，保留报价时间，另记纠正时间和理由；不得靠把旧报价时间改成“现在”绕过新旧判断。后续重建同一来源提取结果不得冲掉人工纠正；真正较新的独立报价仍按统一审核与匹配规则处理。线下新报价的业务时间由人工明确填写并确认，不能把 Excel 导入时间当报价时间。

有效期未提供时显示“有效期未注明”，不承诺永久有效，也不凭空设置过期天数。明确发现报价撤销／作废信息时进入人工复核；本期允许人工停用现行记录并保留原因，不自动回退到旧价格。

### 4.4 价格主表与证据账的区别

价格主表每个完整匹配键至多一个现行状态；旧值不作为可选历史价列表展示。原始证据、提交候选和审核变更记录仍保留，供来源详情和责任追溯使用。不得用“只保留最新状态”作为删除证据、清除审核日志或覆盖原始聊天的理由。

## 5. 规则、LLM 与人工审核

### 5.1 统一流程

聊天提取、网页人工修改、Excel 导入都先形成候选，再经校验／审核，最后通过唯一的生效提交入口；前端、Excel 导入器、LLM 和报告 GET 均不能直接写现行价格。

| 情况 | 决策与行为 |
| --- | --- |
| 公司、路线、规格、币种、计价单位及来源明确，关联唯一，无冲突，规则通过且无需模型参与 | 可自动通过；记录规则版本、证据、系统执行身份及价格责任岗位，不伪造人工审核人。 |
| 当前候选配置为使用 LLM 辅助 | 模型结论返回并完成服务端验证前不得自动生效；模型只给建议、证据和疑点。 |
| 规则或模型提出实质疑虑，二者冲突，引用越界，字段依据不足 | needs_review；由价格审核负责人处理，不覆盖现行记录。 |
| 已启用的模型调用超时、失败、返回非法结构或证据不能核验 | 记录有限的失败原因并转人工；不得静默降级为“模型通过”。 |
| 人工通过或修改后通过 | 必须有配置的实际确认身份；修改后重新验证必填项、类型、范围、匹配键和版本，再尝试生效。 |
| 驳回、待确认、版本冲突、旧报价 | 保持现行值；展示原因与后续处理入口。 |

LLM 的“高置信度”不能单独充当放行条件。规则硬性阻断包括缺失关键身份／范围、证据不存在、歧义路线、非法金额／单位、来源被篡改、并发版本冲突。LLM 不能豁免这些条件，人工也不能通过一个“同意”按钮跳过类型和事务约束；须补充可确认的信息或纠正候选。

网页人工补录或 Excel 改动不能被追认为系统自动从聊天获得。新录入的人工内容需一次显式人工确认，可采用“保存并确认”合并动作，不要求自建双人审批。

### 5.2 模型边界与隐私

- 新价格审核使用独立显式开关，默认不启用外部调用；不能因为机器已有 MiniMax 密钥就自动启用价格审核外发。复用现有客户端时不得改变旧语义分析开关的含义。
- 模型只接收该账号、该业务范围必要的有限证据，先脱敏；不得上传整库、原始企业凭据或附件。开启开关须说明服务商与传输范围，由用户显式启用；本次文档任务不启用或调用模型。
- 输入包含候选、规则结果、允许引用的证据 ID；输出包含建议、结构化疑点及支持引用。所有引用须在输入范围内可核验，不能引用未知消息或把邻近消息当来源。
- 允许综合已明确关联的多条证据，但不补造公司、币种、单位、规格和价格。聊天、引用、Excel 单元格里的“忽略规则／批准报价”等文字一律是数据。
- 外部厂商参数与传输异常放在适配器中；使用有界超时和重试，失败保留候选，禁止在读页面时反复触发计费调用。相同候选及证据／策略版本可复用已验证结果。
- 程序日志只保留必要标识和脱敏错误，不记录 API key、原始响应中的敏感正文或非必要真实公司业务资料。

### 5.3 责任与留痕

配置责任岗位和负责人显示名／本地标识。未配置实际确认身份时可以浏览与生成待审核项，但阻止人工确认、修改生效和人工停用；自动处理不得冒用负责人为“人工审核人”。

每次有意义的审核／变更记录：操作类型、操作者类型（system 或 human）、实际人工身份（若有）、业务责任岗位、UTC 时间、输入候选及版本、证据引用、规则／模型版本、判断方式、理由、变更前后值及最终是否生效。重复同一请求不生成重复生效和重复审核操作。

此机制提供本地操作留痕，不是防篡改账本，不等于身份认证或双人复核。后续若需多人登录、人员不可抵赖或组织审批，应单独扩展，不在本期隐含实现。

## 6. 网页表格与 Excel

### 6.1 网页价格维护

“路线报价与时效”内默认显示“最新价格”，并提供“待审核”入口及数量。当前捕获的原始路线报价不能直接冒充最新价格；旧路线分析口径继续保留在报告接口／必要的汇总说明中。

主表显示七个核心字段、报价公司、币种／计价单位、报价时间、判断方式和待审核提示；来源、负责人及附加条件可在详情中展开。支持公司、路线、状态和关键词过滤；提供查看证据、编辑并提交、审核处理、停用、导入预览、导出及模板下载。编辑须展示旧值与新值，不能将“保存候选”提示为“价格已更新”。

已有现行价且出现待审核新候选时，继续展示现行价，并明确提示“有待审核更新”。没有现行价时不得用待审核金额填充“最新价格”；用户仍可在待审核入口查看完整候选。

### 6.2 Excel 格式与回传

- 一期支持真实 .xlsx 文件；不以重命名 CSV 冒充 Excel，不执行宏、公式或外部链接。旧事件 CSV 导出继续可用，但不能替代价格维护工作簿。
- 工作簿至少包含“价格维护”与“填写说明”。主表前七列依次为起点、终点、重量、体积、包装数量、时效、价格；后续列包含报价公司、单位／币种、报价时间、状态、来源和责任信息。采用单行表头、筛选、冻结表头和清晰列宽，不用合并单元格表示上一行条件继承。
- 往返所需的模板版本、record_id、base_version、来源范围等元数据必须明确标为系统列。人工不能仅修改“审核状态”或“审核人”列就让记录生效；这些值由服务端决定。
- 导出默认是当前筛选范围内全部现行价格，而非当前屏幕页；显式导出待审核项时在名称及状态列区别。脱敏规则与页面一致，真实工作簿保存于被 Git 忽略的本地数据目录。
- 导入先检查模板版本、必需列、行类型、单位、公司解析、来源范围、重复键、记录版本和时间；展示新增、修改、不变、疑点及错误数量，并逐行给出中文原因和旧／新值差异。
- 用户确认导入所选有效行后，进入同一候选／审核入口；人工修改值须经人工确认。存在无效行时不得静默跳过；用户须明确选定允许导入的行，或修正文件后重试。
- 导入预览绑定文件内容摘要、范围和记录基准版本；确认时重新检查。文件内容已变、预览过期或记录被他处修改时拒绝旧预览提交并要求刷新，不默认“后上传覆盖”。
- 缺失 record_id 的行作为新增候选处理，若与现行键冲突则显示差异和待确认，不能按 Excel 行号覆盖。未知单位、价格中的公式、隐藏自动计算、宏文件、非允许格式和超过限制的文件应明确拒绝或标为不可提交。
- 限制上传大小、解压后大小、行数和处理时间；不得跟随工作簿外链，也不得信任上传文件名作为服务器路径。导出外部文本按文字类型写入，防止公式注入。

Excel 读写库若需新增，应在实施时核验其官方支持范围、项目 Python 兼容性及锁定版本，并记录选型理由；通过项目包管理和 uv.lock 维护，不全局安装、不升级无关依赖。

## 7. 聊天证据与信息层级

### 7.1 业务轮次

标题可简化为“业务轮次与回复证据（时间升序）”。每条摘要卡默认展示：时间、提问人 @公司、起终点、简要货物规格、业务状态、回复数量、是否有报价／待复核。轮次编号只是当前展示序号，不能用作持久化价格或证据 ID。

展开后先显示结构化货物／路线摘要与中文状态，再给出按时间排列的提问、补充、确认、报价和跟进回复；提供“查看聊天证据”。不以 JSON、is_solution=true、原始关联枚举和大段哈希作为主阅读内容。首次确认、首次方案、最终方案耗时保持原有含义，不能被运输时效混淆。

### 7.2 统一聊天证据抽屉

轮次、价格行、全量消息都进入同一个聊天阅读组件。默认右侧宽抽屉，支持放大为完整阅读区域；关闭后回到原列表位置、保留筛选和展开状态，焦点返回触发入口。

- 风格参考用户提供的企微“群聊的聊天记录”：浅色背景、日期分隔、姓名 @公司、明确时间、正文留白与消息分隔；不复制水印等无关装饰。
- 多人群聊默认统一左对齐，用身份和语义标签区分参与者；不把某家公司全部摆右侧并冒充“当前登录用户”。确有方向依据时才可使用自己的消息方向。
- 引用以缩进／浅底引用块展示作者、摘要和可定位链接，当前回复正文单独显示。引用不是额外聊天消息，不能重复计数。
- 合并转发显示独立卡片，点击进入其原会话；用“当前记录 → 上一级转发 → 根记录”一类路径导航展示来源层级，不把不同会话正文揉成一条无标识时间线。
- 点击来源定位目标消息并短暂高亮；父级不在当前页时按需获取。父级不存在、未解析或未授权时明确说明，不能生成假的完整证据链。
- 图片／文件／未解析媒体提供类型卡片和“未解析”说明；没有实际媒体时不虚构缩略图和正文。
- “来源详情”二级折叠区容纳原 ID／本地记录键、解析状态、关联依据、哈希、原始身份信息和证据路径，并继续脱敏。
- 支持键盘打开／关闭、Esc 退出、抽屉焦点管理和放大；状态不能只靠颜色识别，长中文、地址和长 ID 均需正确换行。

### 7.3 全量已导入消息

恢复该板块的独立全量浏览能力，而不是继续仅显示“已打开轮次的消息合集”。“全量”指当前账号／会话来源范围内已导入的数据，不宣称全部云端聊天历史。

提供明确的业务轮次／全量消息入口。全量消息默认继承账号和会话范围，可按时间、作者、公司、关键词、消息类型过滤；业务类别／轮次状态过滤若缩小消息范围，必须显式切换为“关联消息”，不能仍标“全量”。显示范围总数、检索匹配数和已加载数。

检索在完整范围执行，不能只搜索浏览器已加载正文。服务端分页或游标加载；阅读顺序为消息时间升序，同秒复用可信原始位置和稳定键，缺失时间单独标注，不伪造时间。分页期间出现新数据时通过稳定快照／游标或明确刷新机制避免重复与漏项。

初始建议每批 100 条、上限 500 条；具体性能参数可基于合成样本调整，但不得把全量正文塞回首屏。定点跳转能够按 ID 拉取目标附近内容，而非依赖用户逐页翻到它。父级证据单列 ancestors，不重复计入当前范围消息数；完整证据导出不受页面分页影响。

## 8. 实现边界与目标契约

### 8.1 设计比较与选择

比较目标是让聊天提取、网页修改和 Excel 回传共享审核及生效规则，防止多处各自实现覆盖逻辑。

| 方案 | 调用契约／示例 | 内部责任与依赖 | 迁移成本及取舍 |
| --- | --- | --- | --- |
| A：读报告时即时算最新价 | 调用 build_report(scope) 得到展示结果；修改只能反写解析字段或旁挂临时配置 | 报告层同时承担聚合、纠正、文件和审核；数据库／网络容易进入读请求 | 表面接口少，但审核难持久化、重建会丢修正、GET 容易产生副作用；不选。 |
| B：分析库中的独立价格维护模块 | submit_candidate → review／apply → list_current；调用方只提交有来源的候选与版本 | 模块封装匹配、审核、新旧判断、事务和审计；复用 SQLite，模型及 Excel 为边界适配 | 需要新增少量表和接口，但规则集中、可从公共操作验证、重建不破坏人工维护；本期选择。 |
| C：Excel 文件作为主账 | 导出并线下修改，再以 sync_workbook(file) 替换网页视图 | 文件锁、冲突合并、审核和证据同步都进入文件交换层 | 与已确认网页主数据矛盾，双主数据风险高，依赖文件位置与编辑工具；不选。 |

选择 B。不引入微服务、事件总线、通用插件框架或第二种数据库。可新增一个集中价格业务模块，具体文件名不是验收条件；只有外部模型判断和真实 Excel 读写需要适配边界。纯归一／匹配在进程内实现，数据库用真实临时 SQLite 测试，不为单元测试制造大量浅层接口。

核心操作契约：提交候选（来源、字段证据、幂等键）返回候选及校验结果；审核候选（动作、实际身份、理由、预期版本）返回审核与采用结果；提交生效在同一事务中验证来源、条件、业务新旧顺序和现行版本，并写价格与审计；查询只读，不触发模型和隐式生效。

### 8.2 逻辑持久化

在现有本地分析库增量新增公司纠正／别名、价格候选、现行价格、审核记录、必要的导入预览和迁移进度。表名和索引由实施者按项目约定确定，但至少满足：

- 稳定的 candidate_id、record_id；现行键唯一；版本单调递增；候选有来源范围、字段证据、规则／模型结果及审核状态。
- 审核状态与采用状态分开：审核通过不代表一定已替换现行值，旧报价或版本冲突仍可不生效；页面须能解释。
- 价格变更与审核结果原子提交；并发审核、Excel 回传和后台提取不能静默互相覆盖。使用 base_version 比对，冲突返回可识别错误。
- 原始消息继续只读作为证据；人工补充为覆盖层。不要把新维护数据挂在会被 rebuild_analysis 删除重建的 issues／responses 行上，也不要给其配置会清除审核数据的级联删除。
- 导入和重建幂等：同一稳定来源报价方案重复处理不产生第二笔生效。原 ID 缺失时沿用明确标记的载荷位置证据键，不冒充原始 ID；无法证明不同转发副本是同一报价时保留疑点，不用内容相似度静默去重。
- 规则／解析器升级可重新生成建议，但已确认的人工纠正和审核记录保留。纠正适用范围变化时提交新候选，不直接改历史结论。

### 8.3 HTTP 与前端边界

以下为本期推荐目标接口；可在不改变语义的情况下遵循项目命名惯例，但须在实施文档中给出最终对应关系，不得缺失操作或让 GET 写数据。

| 接口 | 核心契约 |
| --- | --- |
| GET /api/wecom/prices | 按范围读取 current 或 pending，支持公司／路线筛选、游标，返回 items、total、next_cursor 和范围信息。 |
| POST /api/wecom/price-candidates | 提交网页候选；包含来源／人工依据、base_version 和幂等请求标识，返回候选、校验问题及是否已确认。 |
| POST /api/wecom/price-candidates/{id}/review | approve、reject、correct_and_approve；服务端校验配置身份、理由及版本，明确返回 reviewed 与 applied 状态。 |
| POST /api/wecom/prices/{id}/deactivate | 人工停用现行价格；要求版本、身份、原因并留痕，不删除证据或回退旧价。 |
| GET /api/wecom/prices-export | 导出当前明确范围的 .xlsx；template 模式提供填写模板，导出不触发审核。 |
| POST /api/wecom/prices-import/preview 与 /confirm | 前者只解析并建立预览；后者绑定预览摘要、选择行与版本，进入统一候选／审核流程，不能直接整表覆盖。 |
| GET /api/wecom/messages 与 /api/wecom/messages/{id}/evidence | 独立全量消息检索／分页；按稳定 ID 返回目标、引用、父级及缺口说明，支持非业务轮次消息。 |
| GET /api/wecom/companies；POST /api/wecom/company-corrections | 查询公司与解析状态，预览／提交有范围的纠正和别名映射；影响价格键时转人工复核。 |

新接口使用中文可读 message、稳定 error_code、必要的 field_errors。格式错误返回 400，非法／越界范围或写请求来源返回 403，目标不存在返回 404，版本／重复键冲突返回 409，字段业务校验不通过返回 422；文件过大返回 413，内部失败不得返回敏感栈信息。新写请求包含幂等标识和服务端认可的范围，提交者不能通过请求体伪造自动审核模式、原库认证或任意人工身份。

虽然服务只在本机使用，新增写接口仍须限制 Host／Origin、采用同源写请求校验及防 CSRF 标记、不开放跨域写入，并校验所有 ID 的账号／会话范围。服务器生成或认可的本地操作身份必须与确认记录一致；这不是登录系统，但也不能直接信任 Excel 填入的“审核人”。

前端复用统一聊天组件、公司显示格式和中文状态映射。原有统计页与报告读接口保持只读；候选生成放在显式导入／分析写流程或显式更新操作，不因一次 GET 刷新而触发维护和外部调用。异步请求有加载、错误和过期响应保护，切换筛选后不能显示旧请求返回的详情。

## 9. 兼容矩阵与迁移

### 9.1 固定基线与读写关系

兼容矩阵版本 CM-1。B0 指上文固定的仓库提交及其旧库／接口，B1 指按本规格实施的新版本。运行时基线为项目声明的 Python >=3.11、现有 uv.lock 中 sqlcipher3==0.6.2；本期不顺便升级运行时或数据库依赖。

生产／消费链为：现有导入解析器 → 原始 messages 与派生分析 → 报告／轮次；新增候选生成、网页和 Excel → 统一价格维护模块 → 候选／现行值／审计 → 网页及 Excel 导出。LLM 仅向维护模块返回建议，不能成为存储写入者。

| 组合 | 要求／支持边界 |
| --- | --- |
| B1 读取 B0 数据 | 支持。新增公司解析结果允许未知，新价格表可为空；不得给旧记录自动打人工审核或原库认证标记。 |
| B0 页面读取 B1 的旧 report 接口 | 目标支持。只增加可选公司等字段，旧字段、类别统计、时延及 routes.quotes 原义不变。需实际回归，不能仅凭“增量”断言兼容。 |
| B1 页面连接 B0 服务 | 显示“价格维护接口不可用”，保留旧只读报告入口；不允许伪装保存成功。 |
| B0 读取 B1 数据库 | 仅声明旧消息／报告只读路径目标兼容；须在库副本验证。B0 不理解新增维护数据，不支持用 B0 重建或写入正在使用的新价格库。 |
| B0、B1 同时写同一库 | 不支持。切换前停止旧写入方，不能用发布顺序代替证据。 |
| 新旧 JSON／CSV 消费方 | report 默认完整证据与 view=index 的轻量语义保持；旧 events.csv 的既有 32 列及顺序保持，新价格 .xlsx 独立提供，不无声改变旧导出合同。 |

### 9.2 有边界的阶段

1. Expand：在库副本验证增量表／可选字段与旧读路径；先让新读端兼容旧记录和缺失新接口，暂不自动回填生效。
2. Migrate：经验证的本地数据库备份后，按账号及来源范围分批、幂等生成候选；只对满足新规则的记录更新现行价，歧义进入待审核。记录游标、批次数、错误账和策略版本。
3. Observe：核对旧消息／问题／响应／游标不丢失，公司可解析率、候选数、待审原因、现行键唯一性、重复生效数和导入冲突数；抽检网页、Excel 与证据是否一致。
4. Contract：本期不删除旧字段、不重命名旧表、不移除旧接口，也不清除候选与审核记录。未来收缩须有独立消费者验证和明确授权。

每个阶段记录代码提交、CM-1、数据库备份位置、迁移游标、校验结果及下一步。中断恢复前重新核对代码／数据库／策略版本；不匹配时从最后已验证检查点处理，不盲目重复写入。

恢复优先停止新维护写入并保留新增表以便向前修复。备份恢复不是自动回滚，会丢失备份后的变更；仅在用户授权准确目标与后果后执行。应用回退不能被宣称已撤销数据迁移。

## 10. 验收场景

以下使用脱敏或合成数据测试，不要求向外部服务发送真实聊天。每项须报告实际结果，不得仅以“页面能打开”代替行为验收。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC01 | 提问、回复、嵌套原作者属于不同公司 | 各处显示自己的公司，报价绑定实际报价方，不继承转发者身份。 |
| AC02 | 只有正文 @公司，或企业元数据互相矛盾 | 前者不据此认定公司；后者标待确认，不静默合并。 |
| AC03 | 人工纠正公司及确认简称 | 显示规范结果与依据，原始字段不变；引起价格键冲突时进入复核。 |
| AC04 | 同公司同条件先后报价 620、680 | 完整明确且通过校验后，现行值为 680；主表无历史价格列表，但两次证据及判断可追溯。 |
| AC05 | 两家公司分别对同一条件报价 | 各保留自己的最新价，不互相覆盖。 |
