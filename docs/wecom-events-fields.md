# 企业微信业务事件表字段说明

这份表共有 **32 个表头**。**每行代表一个业务问题及其回复分析，不是单条聊天消息。**

## 表头说明

| 表头 | 中文含义 | 具体说明 |
| --- | --- | --- |
| `round` | 业务轮次 | 本次导出中按提问时间排列的序号，不是原始消息 ID。 |
| `sent_at` | 提问时间 | 原始提问的发送时间；`+08:00` 表示北京时间。 |
| `sender_name` | 提问人 | 提出该问题的原始发送者。 |
| `subject_bucket` | 主体归属 | `zhongji`＝中技方；`other`＝其他企业或外部方；`unknown`＝身份依据不足。依据企业身份判断，正文中的 @ 不改变归属。 |
| `text` | 提问原文 | 本轮问题的消息正文。 |
| `origin` | 起运地 | 从提问中识别的起运城市或地点。 |
| `destination` | 目的地 | 从提问中识别的目的地；存在多个时，该列通常展示首个。 |
| `pickup_address` | 提货地址 | 提问中出现的详细提货地址。 |
| `packages` | 件数与包装 | 首个识别结果，例如 `40ctns`、`6PLT`、`1case`。 |
| `weight` | 重量 | 首个识别结果，例如 `320kgs`，保留原文单位。 |
| `volume` | 体积 | 首个识别结果，例如 `1.77cbm`。 |
| `dimensions` | 尺寸 | 首组识别结果，例如 `800*1200*800mm`。 |
| `special_goods` | 特殊货物 | 如危险品、氢氧化钾溶液、锂电池等。 |
| `first_ack_at` | 首次确认时间 | 首次出现“马上、收到、好的”等即时确认的时间。 |
| `ack_seconds` | 首次确认耗时 | 从提问到首次即时确认的时间差，单位为秒。 |
| `first_response_seconds` | 首条关联回复耗时 | 从提问到首条关联回复的时间差，单位为秒；当前实现也可能计入客户补充信息，因此不宜直接等同于客服响应时间。 |
| `solution_seconds` | 首次方案耗时 | 从提问到首次给出有效报价、时效或处置结论的时间差，单位为秒。 |
| `final_solution_seconds` | 最后方案耗时 | 从提问到当前记录中最后一条有效方案的时间差，单位为秒。 |
| `final_solution_at` | 最后方案时间 | 当前记录中最后一条有效方案的发送时间。 |
| `solution_text` | 最后方案原文 | 最后一条有效方案的回复正文，例如报价、时效、拒单结论。 |
| `status` | 问题状态 | 是否已有方案、仅确认、跟进中或未回复，具体取值见下方。 |
| `source_reference` | 来源定位 | 指向数据库消息、转发卡片及子消息位置，用于追溯证据。 |
| `parent_id` | 父消息标识 | 当前消息所属的上一级转发卡片在分析库中的标识；不是群聊 ID。 |
| `route_items` | 全部路线 | 当前提问中识别出的多组起运地、目的地及识别依据。 |
| `package_items` | 全部件数与包装 | 保留多组结果，例如 `["2PLT","10CTNS"]`。 |
| `weight_items` | 全部重量 | 保留提问中识别出的各组重量，不能直接理解为应相加的重量。 |
| `volume_items` | 全部体积 | 保留提问中识别出的各组体积。 |
| `dimension_items` | 全部尺寸 | 保留所有识别出的尺寸组及原文中的单位、数量后缀。 |
| `document_requirements` | 单证要求 | 如报关、清关、商检、箱单、提单等。 |
| `shipment_constraints` | 运输限制 | 如超长、超重、不可堆叠、不能倒置等。 |
| `route_coverage` | 各路线的方案覆盖情况 | 列出请求的路线、已经匹配到方案的路线，以及尚未匹配到方案的路线。 |
| `needs_review` | 是否需要复核 | `True`＝关联存在歧义或使用了启发式规则；`False`＝未被规则标记，不代表已经人工审核。 |

## 问题状态：`status`

`status` 的四种取值：

| 值 | 含义 |
| --- | --- |
| `solved` | 已有相关报价或明确处置结论。**拒单也属于有结论，不代表已经承运或运输完成。** |
| `acknowledged` | 只有“收到、马上、好的”等确认，尚无方案。 |
| `in_progress` | 已有跟进或正在补充信息，尚无明确方案。 |
| `unreplied` | 当前数据中未找到可关联的有效回复。 |

## 路线方案覆盖情况：`route_coverage`

`route_coverage` 中的三个子字段分别是：

- `requested_routes`：本轮请求涉及的路线。
- `routes_with_attributed_solution`：已能匹配到方案的路线。
- `routes_without_attributed_solution`：尚未匹配到方案的路线。

## 阅读注意事项

**空白或 `null` 表示未提供、未识别或无法确定，不等于 0。**

多组货物、多条路线应重点看 `*_items` 和 `route_coverage`；直接给报价而没有先说“收到”时，`ack_seconds` 可以为空，但 `solution_seconds` 有值。
