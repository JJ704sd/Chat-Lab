实现两条可从头到尾点击、可重置复演的本地 Demo 流程。流程 A 在页面中命名为“价表智能更新 → 最新价卡发布”，完整顺序为“模拟每日索价 → 模拟 @供应商／代理 → 接收多格式多文件回复 → 逐文件解析 → 字段证据 → 跨文件查重与冲突 → 人工审核 → 发布最新价卡 → 检索并回溯来源”。模拟索价必须清楚提示不会发送，不得连接或写入真实企微。流程 B 在页面中命名为“群聊询价识别 → 智能报价”，它对应业务人员所说的第二种空运询价方式，但页面标题不要直接写“方式 2”。流程 B 的顺序固定为“选择本地群聊数据 → 选择账号、来源快照、群聊和时间范围 → 完整性预览 → 用户明确确认导入 → 查看完整聊天证据 → 解析文字、附件和多票截图 → 处理缺失／低置信度字段 → 计算计费重 → 匹配最新价卡 → 内部测算 → 人工确认 → 生成图四式多选项报价预览”。仅发现、列出或预览本地数据时不得写分析库、触发重建或调用外部模型；导入确认必须绑定预览摘要、账号、会话、快照和时间范围，范围变化或预览过期后要求重新预览。

完整性只描述用户选择的本地来源范围，不得宣称企微云端全量历史。预览和导入报告必须显示账号、来源快照、会话 ID、群名、时间范围、根消息数、引用数、嵌套／转发子消息数、附件引用数、本地可验证文件／图片副本数、仅有文件名／sdkfileid／媒体占位而不可取得的附件数、最早／最晚时间、已展开与未展开转发、已解析与未解析媒体及来源认证级别。默认真实场景按用户截图定位 `中技AI cosplay` 在 `2026-09-03` 的目标外层消息；该消息包含“群聊的聊天记录”嵌套卡片，可见 DXB、RUH、STR、FRA、IST 等路线／目的地及重量、体积、尺寸、价格或条件信息。必须通过本机合法来源按会话、消息 ID、父级路径和原始时间找到唯一根消息，读取该根消息的完整嵌套消息树、理解它所必需的相邻外层上下文以及附件关系。截图只作定位和视觉参考，不能作为消息事实数据库；不得用截图 OCR、人工抄录、只取弹窗可见部分或合成记录代替完整本机记录。若本机来源不能唯一定位或完整读取，明确列出候选与缺口并阻塞“真实场景完成”，不得静默降级后仍标为真实。不得按模糊群名自动选中，同名群按账号和会话区分。确认导入必须幂等，只影响选定范围；重导可补充原消息和附件，但不能冲掉人工价卡、审核、价格修正或其他群结果。

建立三层价格模型并在页面、存储、接口和证据中严格分离。第一层是供应商／代理原始价卡：供应商、航司名称／代码、起运机场、枢纽、目的机场／城市、Routing、更新／生效／截止日期、班期、时效、重量档、基础费率、最低收费、币种、计价单位、通用及目的地附加费、限制、单证要求和原始证据。第二层是中技内部测算／维护价：所用价卡版本、毛重、体积重、计费重、重量档、自动费用、未计入歧义费用、内部加价／汇率／舍入规则和完整中间计算。第三层是报价选项：Option、Airline、A/F、Routing、Frequency、T/T、货物摘要、引用的内部测算、价卡版本、限制和人工确认状态。不得把原始成本、内部价和对外预览金额存成同一种记录或互相覆盖。

以用户提供的 ET PDF 与 ET-HK-2026.8.19.xls 作为首个脱敏演示价卡参考，但真实附件不得提交 Git。规范化应覆盖 Ethiopian Airlines／ET、HKG-ADD-目的机场、航程 3-5、班期 D1/2/4/5/6/7、生效日 2026-08-19、+45／+100／+300／+500／+1000 标签、主目的地区域和 Other International Destinations。每个具有明确金额的目的地／重量标签组合拆成 route_rate，不永久固化为五个数据库列；第二分区中有明确五档金额的 BRU、EZE、GRU、JED、KWI、RUH、TLV 可生成费率，仅有 via ADD／over 1000 kgs 等文字条件而无金额的 BLR、BOM、DEL、MAA 只保存为 route_restriction 或 inquiry_required 证据，禁止生成零价或推断费率。+45／+100／+300／+500／+1000 首先只是原始 weight_break_label；自动取档前必须由人工配置并确认边界包含关系、<45kg、>1000kg、计费重取整和命中顺序，未确认时只展示候选档位并转人工，不按最接近或默认上下档取价。价表中的“/”保存为需单询 inquiry_required，不参与自动计费且不推断为禁运；只有明确原文才能标 prohibited。XLS 有效期止为空时不得自行推断，只有关联来源明确写明 until further notice 时，valid_to 才保持 null 并保存相应模式与该来源证据。对 PDF／XLS 配对只把已观察到的“XLS 对应数值 - PDF 对应数值 = 0.20”保存为待人工确认的内部映射候选；附件未证明其商业名称、长期范围或基础费率币种。仅在币种、适用目的地、重量档和启用范围获得来源证据或人工确认后，才按 internal_rate = supplier_base_rate + adjustment_per_kg、adjustment_per_kg = 0.20（继承已确认基础费率币种）参与测算；禁止回写覆盖原始价或编造商业含义。

实现一个统一、多格式、多文件解析批次。首期支持原生和扫描 PDF、XLS、XLSX、DOC、DOCX、CSV、JPG、JPEG、PNG；同一供应商回复或同次上传可含多个不同格式文件。DOCX 必须支持正文、表格和内嵌图片；旧 DOC 仅通过已配置的安全本地转换器处理，转换器缺失时稳定拒绝／转人工。每批建立 import_batch，每文件建立 source_artifact 和 extraction_run，保存文件名、实际类型、MIME／魔数、大小、哈希、消息来源、接收时间、安全状态、解析器版本、状态、页／表数量、警告和错误。聊天中的附件引用和已取得文件必须分开：只有本地快照或规范化包中有可验证本地副本且哈希／范围匹配的附件才能解析和预览；只有文件名、sdkfileid 或媒体占位而没有二进制副本时标 referenced_but_unavailable，不自动下载、不伪造预览、不计入已取得附件。单文件失败不能阻断其他文件，但未处理关键文件时整批不得标记全部完成。扩展名和实际类型不一致、密码保护、损坏、超限或缺少安全转换器时拒绝或转人工；禁止执行 Office 宏、Excel 公式、外部链接、Word 域代码、PDF JavaScript、远程资源和附件内指令。解析使用隔离临时目录，不覆盖源文件，设置有界的文件数、大小、页数、工作表数、像素和资源限制。

采用“原生结构优先、本地 OCR／布局分析其次、人工兜底”。Excel／CSV／Word 表格和原生 PDF 优先读取结构、显示值、表格、单元格和合并关系，不先转成图片；扫描 PDF、Word 内嵌图片、JPG／JPEG／PNG 进入本地 OCR 和视觉布局分析。实施时选择并记录一个目标机器可运行的本地 OCR 基线及版本，准备至少一张满足其质量要求并能稳定识别的脱敏夹具；引擎缺失、图片低清／裁切／旋转／遮挡或布局不能可靠恢复时，稳定返回 needs_manual_review、原因和原图证据，不伪装成功，也不承诺任意图片均能还原完整表格。每个字段必须保存 field_evidence：原始值、规范值、解析器版本、置信度和可定位来源。PDF 定位到页、表格／块和矩形区域；Excel 定位到工作表和单元格／范围；Word 优先定位到段／表格／单元格／内嵌图片，只有稳定渲染后才补充页码；CSV 定位到行列；图片定位到矩形区域和视觉行组；聊天定位到账号、会话、消息 ID、作者、时间、引用和父级路径。人工修正保留原值、修正值、操作者、时间和理由，不能把人工值伪装为 OCR／模型值。

默认不得把真实聊天或附件发送给外部视觉模型。外部视觉模型只作为独立、可插拔、显式配置的增强：必须展示服务商、模型、传输数据类型和脱敏范围；不能因为已有 MiniMax 或其他文本模型密钥就自动开启。未配置外部模型、模型超时、失败或返回非法结构时，本地解析、规则和人工流程仍须完整可运行。模型只能产生带当前批次有效证据的候选，不直接发布价卡或确认报价，不补造币种、价格、单位、航司、机场、有效期、路线、重量或限制，不得引用范围外消息／文件／页码／坐标，也不得用自报高置信度绕过服务端硬规则。

多文件规范化后统一查重。价卡可比键至少包含供应商／代理、航司、起运机场、目的机场、路线、重量档、币种、计价单位、适用条件和生效范围，金额不属于键。先用 valid_from／valid_to 判断版本在目标询价日期是否适用；对同时适用的同键版本，依次比较明确的 valid_from、文件更新日期 document_updated_at、群聊接收／人工上传时间。日期只有月份、解析冲突、有效期范围重叠而无法排序，或文件内更新／生效日期互相矛盾时形成日期冲突，不自动发布。同键同优先级同值可合并证据；同键不同值必须形成冲突组，由人工选择、修正或暂存，绝不静默覆盖。不同供应商、航司、机场、重量档、币种和适用条件不得因数值接近而合并。所有新增价卡、价格更新、人工修正和冲突决策进入统一候选池，只有配置了实际审核身份并明确确认后才能原子发布；记录候选版本、变更前后值、证据、确认人、时间、理由、规则／解析器版本和幂等键。空运 rate_card_version、route_rate 和内部费率规则不得调用旧通用价格模块“规则完整即可自动采用”的分支；只有实际审核人执行通过并发布／修正后发布才能改变空运现行价卡，旧揽收接口保持旧语义并按业务线隔离。未配置审核身份时只允许解析和预览。原始文件和提取证据永不因发布、停用或冲突决定而改写／删除；只有审核通过的版本是已发布价卡，版本切换只改变 published_current 指针或等价状态。

将附加费和限制分为可计算规则与提示规则。只有金额、币种、单位、计重基准、最低收费、适用范围和生效条件都明确时才自动计入内部测算，并展示公式和来源；目的地附加费、分泡规则、尺寸／重量限制、危险品／电池要求、Small Box、单证要求或其他条件存在歧义时，不加入总价，必须展示原文、影响范围、未计入原因和人工确认项。未知、空白、零、不适用和需单询是不同状态；缺失币种、单位、路线、重量档或适用条件时不得生成可确认的最终报价。

实现 cargo_component 与 package_group 两级货物结构。cargo_component 保存 Unit、QTY、描述和所属包装组；package_group 保存长宽高和单位、Gross Weight、CTN／package_count、尺寸／重量／CBM 是单件值还是整组总值、图片行组及证据。对可能出现的 Unit／QTY 多行和包装字段跨行合并版式，按视觉行组和表格边界判断；无法确认合并关系时转人工拆分。跨行值只累计一次，两个独立包装即使尺寸相同也不得自动合并；Demo 使用脱敏合成夹具覆盖该场景。保留原始文本和数值，未知不填零。只有尺寸确认是单件／单箱尺寸且 CTN 确认是对应件数时，才令 package_count = CTN 并在体积公式中相乘；若尺寸是整组外廓则不得再次乘 CTN，CTN 或单件／整组语义不明时阻止自动体积重。尺寸和 CBM 同时存在时计算几何体积并展示差异，不静默覆盖。Demo 对单件尺寸使用 length_cm × width_cm × height_cm × package_count ÷ 6000，对整组外廓使用 length_cm × width_cm × height_cm ÷ 6000，再按包装组求和；总计费重取正确归一后的总毛重和总体积重较大值。系数和舍入规则可配置，界面明确标注演示规则并显示逐包装公式、中间结果、总数和差异。

一张图片或聊天上下文可包含多票、多包装和多路线。先识别表格、合并区域、视觉行组和消息关联，再形成相互隔离的 quote_request；每票保留图片区域和聊天证据。无法唯一确定票、路线、包装或价格归属时，进入人工拆分，不把规格与路线做笛卡尔积，不把一个裸价格复制到多个路线。低置信度字段在原图或原文旁高亮，用户可以修正；缺失项可在 Demo 中模拟“追问 → 回复”，但不得真实发送。根据已发布价卡为同一询价生成多个航司／路线报价选项，各选项独立使用自己的重量档、班期、时效、附加费和限制。

重构前端为清晰的空运信息架构，至少包含空运概览、流程演示中心、本地群聊导入、价表解析批次、最新价卡、询价与货物明细、内部测算与报价预览、待审核与证据。演示中心不能再以横向步骤条和四个同权重说明框作为主体；桌面首屏采用“左侧流程章节／场景导航 + 中央企微模拟主舞台 + 右侧 Agent 执行轨迹”的清晰层级，中央舞台始终是视觉焦点。两条流程共用同一外壳，切换后保留各自状态。中央舞台按业务时间线持续累积消息、引用、嵌套转发、附件、Agent 处理卡和人工决定卡，逐步形成完整故事，而不是每步替换一段抽象说明。复用现有企微视觉：中技方右侧浅绿、已确认供应商左侧白色、未知身份中性；支持日期分隔、姓名与公司、引用、完整递归转发、附件、目标定位、相邻上下文、Esc 和焦点恢复。真实本地消息保留来源身份和时间；为补齐 SOP 增加的内容始终标“演示模拟”；解析、查重、风险、审核和发布只用 Agent／人工卡，不伪装成供应商气泡。不得从公司名猜测消息方向，转发子消息使用原作者。技术哈希、绝对路径和解析器版本只进入受控来源详情，不能混入聊天正文。

主舞台每步只突出一个结论、一个主动作、一个关键结果和下一步提示。需要查看完整内容时，用户主动点击“查看完整结果／查看来源证据”，页面再打开或平滑定位到下方实际业务区，高亮与当前步骤绑定的记录，并提供“返回演示主舞台”；禁止步骤完成后自动长距离滚屏。A6—A8 分别映射待审核与证据／最新价卡，B1—B5 映射本地群聊导入，B6—B8 映射询价与货物明细，B9—B12 映射内部测算与报价预览。下方业务按钮绑定当前 demo_run 时必须同步更新同一服务端步骤与事件轨迹；未绑定时明确标为独立操作。流程结束先在企微主线展示完成卡，再显示只汇总本次 demo_run 和选定真实范围的“本次演示成果”看板；看板至少包含文件成功／失败、冲突、已发布价卡、询价票、计费重、报价选项、未解决风险和人工决定，且可回到对应步骤和证据。
