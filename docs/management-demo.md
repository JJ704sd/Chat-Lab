# 双链路运价维护演示

目标是在约 5 分钟内说明：供应商 PDF 和群聊报价都能自动整理为待审核价格；人工确认后进入统一价格表，随时查看原始依据。

视觉参考为 [原始 design.md](design.md)。采用其中的中技品牌红、深红导航、暖白内容区、语义状态、渐进披露和固定主操作规则；原文中的工单与邮箱业务不作为本次功能范围。

## 启动

需要 Python 3.11+ 和项目依赖（PDF 解析、原页预览使用 pdfplumber）。

使用项目既有的 uv 安装锁定依赖并启动（Mac / Windows 通用）：

```sh
uv sync --locked
uv run --locked python scripts/start_management_demo.py
```

如果当前 Python 已安装项目依赖，也可直接使用以下启动命令。

Mac：

```sh
python3 scripts/start_management_demo.py
```

Windows：

```powershell
py -3 scripts/start_management_demo.py
```

打开 `http://127.0.0.1:8891/`。默认只监听本机；可通过 `--port`、`--data-root` 改变端口或独立演示数据目录。Mac 已实机验证；Windows 已验证同一入口启动、首页与价格表导航，真实资料完整链路需另行导入资料验收。

## 新环境构建与资料准备

本项目使用 Hatchling 构建 Python 包，网页是随 wheel 打包的静态资源，无需 npm 安装或前端编译。可用 `uv build` 生成源码包和 wheel。

真实资料不随 Git 分支分发。首次启动看到空页面数据属于正常状态：

- PDF：在首页点击“更换 PDF”，导入支持的 Trimanson ET co-load 价表。
- 群聊：将已获授权且已脱敏的 `source-chat.json` 放到所选数据目录的 `presentation/` 中；使用 UTF-8 编码，数据格式和来源要求见下文。
- 缺少资料时不能执行对应链路，但可正常查看价格表并返回演示首页。

Windows 读取演示 JSON 时明确使用 UTF-8；价格库连接在事务提交或回滚后关闭，避免持续占用 SQLite 文件。测试资料也使用 UTF-8 中文原文，覆盖跨平台读取。

## 推荐讲解顺序

| 环节 | 操作 | 讲解重点 |
| --- | --- | --- |
| PDF 链路，约 2 分钟 | 点击“模拟 09:00 索价”，再进入审核 | 机器人右侧 @供应商，供应商左侧回复真实文件，自动解析后停在人工审核 |
| PDF 审核 | 点击“一键准备演示资料”自动选取示例并补齐，再点击“审核通过” | 同一份文件支持人工勾选批量审核，每条价格独立留存原件位置 |
| 群聊链路，约 2 分钟 | 点击“回放真实询价”，进入逐条审核 | 我方业务在右侧，供应商在左侧；Agent 将报价和询价依据一起整理 |
| 群聊审核 | 点击“一键准备演示资料”选择清晰报价并补齐，再点击“审核通过” | 一次只允许审核一条；缺失或歧义不会被自动补造 |
| 统一价格表，约 1 分钟 | 查看两类来源的已生效价格，点击“查看依据” | 同一价格库，人工审核后生效；PDF 页码、聊天和审核记录可以追溯 |

“一键准备演示资料”只准备界面，不提交审核。PDF 默认选当前重量档最多 3 条可用价格（保留已勾选项；当前档已处理完会自动换到有待审核价格的档位）；群聊只选择 1 条价格清晰的真实报价。保留已有输入，缺失的交仓地、币种、单位或期限用演示预设补齐，并在审核结果和证据详情中保留“含演示预填”标记。原始报价数值与依据不改写，仍需点击“审核通过”才生效。

“修改提取字段”按需展开价格、航司、重量档等完整编辑项。主操作固定在底部；默认核对表单与来源并排。价格表中可按航点、航司、供应商搜索。

点击“新一轮演示”创建空白演示价格库，上一轮数据和审核记录保留在同一个独立演示数据库中。不会删除原 PDF、聊天或既有业务分析库。

## 审核和版本规则

1. 获取与整理只创建 `pending` 候选；没有规则或模型自动批准入口。
2. PDF 支持多条勾选审核；批量修改只允许共同的交仓地和适用期限，其余字段需逐条修改。群聊一次只允许一条。
3. 勾选价格后点击“审核通过”即可，不要求填写备注或另勾原文确认。审核人、时间、动作和来源自动留存；币种、单位、交仓地、目的港、重量档、价格与期限等必要业务字段缺失时仍需补齐。驳回同样不要求备注，也不入表。
4. 审核、价格写入和记录留存作为一个事务执行；某条失败时整批不生效。已处理的重复请求返回冲突，不重复入表。
5. 后续新报价先进入待审核；通过前原价格保留，通过后产生新版本并保存前后值。旧报价不能回滚更新的价格。
6. PDF 保留原件指纹、页码、行和价格档。即使更换 PDF，旧价的证据仍指向旧原件。聊天保留询价和供应商回复，现场补充字段标记为人工修改。
7. 群聊现货报价保留本票货量范围，不自动提升为整条航线通用运价。PDF 基础运价不自动变为含附加费的全包价。

审核身份固定显示“价格审核负责人（演示）”，仅用于本地演示；不代表生产系统身份认证或真实业务审批。

## 演示边界

09:00 索价、@供应商、供应商回传是明确标注的模拟事件，附件是用户提供的真实文件，不能声称这些事件发生在真实群里。不会向企业微信发送消息，也没有创建真实定时任务。

群聊按提前导入的真实数据回放。本地结构识别用于展示 Agent 整理效果，本轮没有调用外部模型。Mac 本地界面运行已验证，不代表企微原库自动采集已实现；原库验证仍见 [Mac 本地采集报告](wecom-macos-local-feasibility.md)，未修改客户端签名或运行方式。

此前连续批量向前翻页被自动审批拒绝，原因是可能越出最近一天范围；未绕过限制，沿用已取得样本。

正式部署仍需接入获授权的消息来源、调度与机器人发送接口、解析服务及真实审核身份。当前价格库只为演示服务。

## 文件与接口

真实资料保存在 Git 忽略目录 `data/management-demo/presentation/`，不会随源码提交：

- `source-chat.json`：提前导入的脱敏群聊。
- `rate-<sha256>.pdf`、`active-rate.json`：不可变原件与当前解析结果。这里的 active 仅指当前导入资料，不代表已审核价格。
- `pricing-demo.sqlite`：独立演示轮次、候选、已生效价格和审核记录。
- `drafts/`：上一版报价草稿兼容数据，已退出主演示流程。

新模块为 `sources/pricing_demo.py`，界面为 `static/management.html`、`management.css`、`management.js`。原 PDF 提取与群聊归集模块继续复用；未调用旧价格模块的自动采用分支，未改变旧工作台业务库。

- `GET /api/airfreight/presentation/pricing`：只读资料、候选、价格和审核记录。
- `POST /api/airfreight/presentation/pricing/prepare`：整理指定链路，重复导入不撤销审核。
- `POST /api/airfreight/presentation/pricing/review`：带轮次、来源版本、候选和审核动作执行人工审核，不要求备注或额外确认字段。
- `POST /api/airfreight/presentation/pricing/new-run`：保留旧轮次，开始新演示。
- `GET /api/airfreight/presentation/page`：真实 PDF 原页图像。
- `GET /api/airfreight/presentation/rate.pdf?sha256=...`：按原件指纹读取 PDF。

新写接口沿用服务端同源和 CSRF 检查。原详细空运工作台保留在 `/workbench`，旧揽收页为 `/legacy/pickup`。

## PDF 原件阅读工具

## 精选案例内容审核

按用户要求，主演示从按会话日期堆叠消息改为按业务情节筛选。当前保留 3 类、5 笔询价、9 条可解释的报价候选：
